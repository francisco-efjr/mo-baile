## O que é

Um relato avisa a equipe sobre um erro ou sugestão. O app prepara uma issue pública no GitHub com as informações que você escolher.

> Atenção: o relato é público no GitHub. Qualquer pessoa pode ler o que você enviar.

## Quando usar

- Quando algo falhar, travar ou se comportar de forma estranha.
- Quando a Ajuda não resolver o seu caso.

## Passo a passo

1. Abra o menu **Ajuda › Relatar um Problema…**, ou clique no selo **Beta** na barra de status.
2. Preencha o título, escolha a área e conte o que você fez, o que esperava e o que aconteceu.
3. Marque os anexos e os dados opcionais que quiser incluir. Nada opcional vai sem a sua marca.
4. Confirme. O app abre uma issue pré-preenchida no GitHub e mostra no Finder a pasta com os anexos.
5. Arraste os anexos para o campo de descrição e publique a issue.

## Exemplo prático

Ao exportar um HAR, o Mo baile fecha. Abra **Ajuda › Relatar um Problema…**, escolha a área Rede HTTP e escreva "Exportar HAR fecha o app". Diga que esperava salvar o arquivo. Anexe o log e deixe os dados opcionais desmarcados. No GitHub, arraste o log para a descrição e publique.

## Recursos

- **Título e área**: ajudam a equipe a achar o responsável.
- **O que você fez, esperava e aconteceu**: o trio que permite reproduzir o problema.
- **Anexos**: arquivos que o app reúne numa pasta aberta no Finder.
- **Dados opcionais**: só entram no relato se você marcar.
- **Sem o app**: abra `https://github.com/francisco-efjr/mo-baile/issues/new/choose` no navegador.

## Problemas comuns

- **Não consigo publicar a issue.** Você precisa de uma conta gratuita no GitHub. Entre nela e tente de novo.
- **Os anexos não subiram sozinhos.** É esperado: arraste-os da pasta do Finder para a descrição.
- **Quase incluí um dado sensível.** Nunca inclua senhas, tokens, CPF, e-mails, dados de clientes ou tráfego de produção. Edite antes.
